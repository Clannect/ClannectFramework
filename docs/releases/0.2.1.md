**Sound and game input**: a new module, cfw-audio, and relative mouse mode, key positions, touch and gamepads in
cfw-platform. Nothing was removed or renamed.

This is a **pre-1.0** release: CFW runs Clannect today, but the API may change between versions.

## Downloads

| File | What it is |
|---|---|
| `ClannectFramework-windows-x64-online-installer.exe` | **Windows, recommended.** Installs any published version for MinGW-w64 GCC 13 (64-bit), and can tell you when a new one is released. |
| `ClannectFramework-0.2.1-windows-x64-offline-installer.exe` | **Windows, no internet needed.** Installs 0.2.1. |
| `ClannectFramework-0.2.1-windows-x64-mingw.zip` | The same Windows package as a zip, for scripts and CI. |
| `ClannectFramework-0.2.1-linux-x64.tar.gz` | Headers, static libraries and CMake package for **Linux x64** (GCC 13 or Clang 18), with `bin/cfw-ui-gallery`. Built on Ubuntu 24.04: the gallery needs glibc 2.39 or newer and libX11. |
| `ClannectFramework-0.2.1-macos-arm64-EXPERIMENTAL.zip` | **Experimental**, and only present if it built: this release's macOS code (sound output, relative mouse mode, gamepads) was written without a Mac and had not been compiled when the release was tagged. |
| Source code | Build CFW yourself with any supported compiler. |

The prebuilt libraries only work with the compiler family they were built with (Visual Studio is not supported
yet). If yours differs, build from source or use CMake's FetchContent, as the README shows.

## Using an installed version

```cmake
find_package(ClannectFramework 0.2 REQUIRED)
target_link_libraries(my_app PRIVATE cfw::app cfw::audio)
```

On Windows, if you let the installer register the version with CMake, that is all. Otherwise, and for the zips,
configure with `-DCMAKE_PREFIX_PATH=<the installed or unpacked folder>`.

## What's new since 0.2.0

- **cfw-audio (new):** sound output through the system's default device (WASAPI on Windows, ALSA on Linux loaded
  at run time, CoreAudio on macOS), pulled by a callback at 48 kHz stereo float, following the default device.
  CFW's own WAV, Ogg Vorbis, MP3 and FLAC decoders, whole-file and streaming with seeking, with the format
  detected from the bytes. An offline resampler for clips and a streaming one. A null device for tests.
- **Relative mouse mode:** `Window::setRelativeMouse` hides and holds the cursor and reports the mouse's raw
  movement in `PointerEvent::delta` (Raw Input, XInput 2). `Window::setCursorConfined` keeps a visible cursor in
  the window.
- **Keys by position:** `KeyEvent::physicalKey` beside `key`, and left and right modifiers (`Key::LeftShift`...).
- **Touch and pen:** `Window::touch` reports every contact with an id; the primary one still arrives on
  `Window::pointer` as the mouse.
- **Gamepads:** `cfw::Gamepads`, with the standard layout, raw buttons and axes, events and polling, rumble, and
  virtual pads for tests.
- `Surface::startTimer`'s behaviour when a repeating callback is slower than its interval is now specified and
  tested; `writeFileAtomic` is confirmed (and tested) for targets on another volume than the temporary directory;
  `Quat::fromAxes` and the Euler conversions have round-trip tests.

**What is verified and what is not** is spelled out per platform in the README's Sound and Input sections. In
short: the decoders and the Windows and X11 mouse and keyboard code are tested on Windows and Linux; the ALSA
device was only run against ALSA's null device; touch, pen and gamepads were not tried with hardware; and none of
this release's macOS code has been compiled.

**For code written against 0.2.0:** `PointerEvent::Type` gained `Cancel` and `Key` gained the eight sided
modifier keys, which a `switch` without a `default` will be warned about. On macOS, `KeyEvent::key` is now the
key the layout produces, as on the other platforms. `docs/migration/engine-audio-and-input.md` has the details.
