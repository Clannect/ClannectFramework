How CFW is tested

CFW replaces libraries that have had decades of hardening, so it is tested against them directly.

Reference outputs

The reference implementations run outside the build to produce the expected results. They are never linked into CFW.

AreaChecked againstHow close
PNG decodingAll of PngSuiteExact.
JPEG and WebP decodinglibjpeg-turbo and libwebpExactly the same pixels.
FLAC decodingThe reference encoder's filesBit for bit.
Vorbis and MP3 decodingFFmpeg's decodersSample by sample, to float rounding.
Font parsingfontTools and FreeTypeGlyph for glyph.
Text shapingHarfBuzzEvery glyph id, cluster and offset.
Text algorithmsUnicode's conformance testsAll pass.

Fuzzing

Every parser has a libFuzzer target: JSON, URLs, HTTP, WebSocket frames, compression, PNG, JPEG, WebP, the four sound formats, fonts, SVG, shaping and painting.

The corpus is committed in fuzz/corpus and is replayed in every build, so an input that once crashed a parser is checked forever after.

Sanitizers

CI runs the whole suite under AddressSanitizer, UndefinedBehaviorSanitizer and LeakSanitizer, and the networking code under ThreadSanitizer. One report fails the job. The presets are in Build presets.

Real system clients

Some features only mean something next to the real system component, so that is what the tests use:

  • Input methods: a real X input method.
  • Screen reader support: the AT-SPI registry on Linux, and Windows' own accessibility APIs under Wine.
  • Drag and drop: the system's own protocol.
  • Keyboard and mouse: input injected through the X server (XTEST) and the Windows input stack.

Soak tests

Long randomised runs of the network stack and the widget toolkit. Set CFW_SOAK_SECONDS to make them run longer.

Warnings are errors

CFW's own code is built with warnings as errors, in every CI job.

What is not verified

Where something has not been checked on a real system, the README says so, cell by cell, in its tables for sound and input. The largest gaps today are macOS and physical input devices.

If you send a change

Add tests with it, and make sure ctest --preset debug passes with no warnings. Pull requests are also scanned by the security checks.
