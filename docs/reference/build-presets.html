Build presets

The CMake presets in CMakePresets.json, and what each one is for.

Using a preset

A preset has the same name for configuring, building and testing. Each builds into build/<preset>.

cmake --preset release
cmake --build --preset release
ctest --preset release

The presets

PresetUse
debugEveryday development: contract checks and bounds-checked containers.
releaseOptimised, checks off.
asanAddressSanitizer, UndefinedBehaviorSanitizer and leak checks.
tsanThreadSanitizer (Linux).
ubsan-trapUndefinedBehaviorSanitizer without a runtime library. Works with MinGW.
fuzzClang and libFuzzer: a fuzz target for every parser.
Sanitizers on Windows

MinGW cannot run AddressSanitizer or ThreadSanitizer. On Windows use ubsan-trap; run asan, tsan and fuzz on Linux, as CFW's CI does.

Choosing a compiler

Pass the compiler when you configure:

cmake --preset debug -DCMAKE_CXX_COMPILER=clang++

Building for Windows from Linux

CFW has a toolchain file for the MinGW-w64 cross-compiler:

cmake -S . -B build/windows -G Ninja -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/mingw-w64-cross.cmake
cmake --build build/windows
ctest --test-dir build/windows

The tests are Windows programs, and run under Wine.

Longer soak tests

The soak tests are long randomised runs of the network stack and the widget toolkit. Set CFW_SOAK_SECONDS to make them run longer:

CFW_SOAK_SECONDS=600 ctest --preset debug
