Read input

How a game or an editor reads the mouse, the keyboard, touch, a pen and gamepads through cfw-platform.

A first-person camera: relative mouse mode

For a camera you want the mouse's own movement, not the position of a cursor that stops at the edge of the screen. Turn on relative mode, and read PointerEvent::delta:

window->setRelativeMouse(true);   // raw deltas, cursor hidden
cfw::ScopedConnection c = window->pointer.connect([&](const cfw::PointerEvent &e) {
    camera.turn(e.delta);
});
  • The cursor is hidden and held in place.
  • delta is unaccelerated, and the screen's edge does not stop it.
  • Relative mode ends when the window loses the focus. The window says so through relativeMouseChanged, so you can show a "click to continue" screen.

To keep a visible cursor inside the window, use Window::setCursorConfined instead.

Keys: what was typed, and where it is

Every key event carries two answers, because games and shortcuts need different ones:

FieldWhat it isUse it for
keyWhat the user's keyboard layout produces.Shortcuts: Ctrl+S should be the key labelled S.
physicalKeyThe position of the key, by its name on a US layout.Movement: W, A, S, D should be the same four positions on every layout.

Left and right modifiers are told apart in physicalKey (Key::LeftShift, Key::RightShift and so on). key stays Key::Shift.

Touch and pen

Window::touch reports every contact, each with an id, so you can follow several fingers.

The primary contact also arrives on Window::pointer as the left mouse button. Code written for the mouse works with a finger or a pen unchanged.

Gamepads

#include "cfw/platform/Gamepad.h"

auto pads = cfw::Gamepads::create();
// then, once a frame:
pads->poll();

You get the standard layout, plus the raw buttons and axes for pads that do not fit it. You can read pads by polling or by events, and make them rumble. There are virtual pads for tests.

See every event

The example program examples/input-events prints every event it receives. Run it with a real mouse, keyboard and pad to see exactly what your hardware sends:

cfw-input-events
