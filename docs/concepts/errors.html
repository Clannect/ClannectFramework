Errors and Result

CFW does not throw exceptions for errors. A call that can fail returns a Result<T>: either the value, or an Error that says why not.

Reading a Result

Check it, then take the value or the error:

#include "cfw/core/Result.h"

auto created = UiWindow::create({"Hello", {480, 320}}, Theme::dark().withSystemFonts());
if (!created) {
    std::fprintf(stderr, "%s\n", created.error().describe().c_str());
    return 1;
}
UiWindow &window = *created.value();
MemberWhat it does
ok(), or use it as a boolTrue if it holds a value.
value()The value. Only call it on a successful result.
error()The Error. Only call it on a failed result.
valueOr(fallback)The value, or fallback if it failed. The error is dropped on purpose.
Check before you read

Calling value() on a failed result, or error() on a successful one, is a contract violation. It stops the program, in every build, release builds too.

You cannot ignore one by accident

Result is marked [[nodiscard]], so the compiler warns when a returned result is thrown away. CFW's own code is built with warnings as errors, so there it does not compile.

Returning a Result

Return the value for success, or an Error for failure. Both convert to the result:

#include "cfw/core/Result.h"

cfw::Result<int> parsePort(const cfw::String &text) {
    int port = 0;
    if (!toInt(text, port)) {   // toInt stands for your own parsing
        return cfw::Error(cfw::ErrorCode::ParseError, "not a number").with("text", text);
    }
    if (port < 1 || port > 65535) {
        return cfw::Error(cfw::ErrorCode::OutOfRange, "port out of range");
    }
    return port;
}

A function that produces no value returns Result<void>. Return cfw::success() when it worked:

cfw::Result<void> save(const Settings &settings) {
    if (!settings.valid()) {
        return cfw::Error(cfw::ErrorCode::InvalidArgument, "settings are incomplete");
    }
    // ...
    return cfw::success();
}

What an Error holds

MemberWhat it is
code()An ErrorCode: the kind of failure, for code to switch on.
message()A sentence for a person.
context()Optional key and value pairs, such as a file name, a line or a byte offset.
with(key, value)Adds context and returns the error, so it chains on a return.
describe()All of it in one line, for example ParseError: bad token (line=3, column=7).

Limits

  • Result<T&> is not supported. Return a pointer, or a Result<T*>.
  • Result<Error> is not allowed: it would be ambiguous.
