Modules and platforms

CFW is ten modules in layers. You link the ones you use, and nothing else comes along.

The modules

ModuleWhat it gives you
cfw-coreStrings and UTF-8/16, containers, math (vectors, quaternions, matrices), colours, Variant, properties, signals, Result and Error, logging, arenas, SHA-256, UUIDs, URLs, locale-aware number formatting, and DEFLATE/zlib compression.
cfw-ioFiles and paths (UTF-8, atomic writes, memory mapping), JSON with precise error positions, a binary reader and writer, zip archives, per-user settings and standard folders, processes.
cfw-netAn event loop, TCP, TLS 1.2 and 1.3 through the operating system, an HTTP/1.1 client, and WebSocket client and server.
cfw-imageImage; PNG and JPEG decoding and encoding, WebP decoding; resizing and an atlas packer.
cfw-audioSound output through the system's default device; WAV, Ogg Vorbis, MP3 and FLAC decoders; resamplers. See Play sound.
cfw-textUnicode 18 (grapheme clusters, line breaking, bidi), a TrueType/CFF font parser, OpenType shaping, text layout, font fallback and a glyph atlas.
cfw-gfxA 2D Painter: paths, pens, dashes, gradients, images, transforms, clipping and blend modes, on an anti-aliased CPU rasteriser; SVG icons.
cfw-platformNative windows, keyboard, mouse, touch and pen, gamepads, input methods, file drag and drop, the clipboard, cursors, high-DPI, and OpenGL 3.3 contexts. See Read input.
cfw-uiA retained widget toolkit: layout, focus, themes, buttons, text fields, menus, dropdowns, sliders, tree views, tabs, dockable panels, property grids, dialogs, a colour picker and more.
cfw-appPuts it together: UI windows, screen reader support, native file and folder pickers, opening links.

How they depend on each other

Each module is a CMake target, cfw::core to cfw::app. Linking a module brings in the ones it depends on, directly or through another module:

ModuleDepends directly on
cfw-coreNothing: the C++ standard library and the operating system.
cfw-iocfw-core
cfw-netcfw-core
cfw-imagecfw-core
cfw-audiocfw-core
cfw-textcfw-image, cfw-io
cfw-gfxcfw-image, cfw-text
cfw-platformcfw-image
cfw-uicfw-gfx, cfw-text
cfw-appcfw-io, cfw-platform, cfw-ui

So a headless game server links cfw::core, cfw::io and cfw::net, and has no window, font or image code in it at all.

Platforms

PlatformStatus
Windows (MinGW-w64 GCC 13)Supported.
Linux (X11; GCC 13 or Clang 18)Supported.
macOS 13.3 or newer (Apple silicon)Experimental: it builds and passes the tests on GitHub's macOS runners, but no person has tried it on a real Mac yet.
Wayland

There is no Wayland backend. On a Wayland desktop, CFW runs through XWayland.

No third-party dependencies

Everything CFW needs, from PNG and MP3 decoding to OpenType shaping, is implemented in the repository. TLS is the one thing it does not implement: it uses the operating system's. The reasons are recorded in the design decisions.
